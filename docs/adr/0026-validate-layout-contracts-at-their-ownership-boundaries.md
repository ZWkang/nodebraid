# Validate Layout contracts at their ownership boundaries

Layout validation is split by ownership: the shared projection rejects invalid Requests, Fixed Node IDs, missing Sizes, and nesting; each Provider validates its typed configuration and algorithm constraints; Runtime validates Proposal revision, exact Node coverage, finite coordinates, and unchanged Fixed Nodes before checking the live revision immediately before commit. NodeBraid copies and freezes its Input, Capability, and validated Proposal shells, accepts explicit zero dimensions, and canonicalizes graph and result order by ID so the same Provider version, input, and effective configuration produce deterministic coordinates. Shared structural failures use only `INVALID_REQUEST`, `INVALID_INPUT`, `UNSUPPORTED_FEATURE`, `INVALID_PROPOSAL`, and `STALE_PROPOSAL`, with bounded diagnostic details rather than copied graph or domain data; Provider-specific failures retain their original values. Cancellation is checked around every asynchronous boundary, while valid empty and all-fixed inputs still exercise the Provider contract instead of taking a silent shortcut; Kernel remains the final authority for Transaction graph invariants.

The initial rejection of Port Endpoints is superseded by the [approved Node-topology Layout scope](https://github.com/ZWkang/nodebraid/issues/37). Both ordinary and Port-qualified Edges project to their distinct Edge IDs and endpoint Node IDs, so Dagre and ELK can arrange Nodes without interpreting Port definitions or geometry. Layout requires no PortService, Port Snapshot, or contribution generation and performs no Port existence, role, or definition validation; Renderer retains Port Geometry ownership under [ADR-0082](0082-split-port-connection-ownership-by-semantics.md). The commit changes only Node positions and preserves Edge Endpoints and `portId`; any Document revision change, including an Endpoint edit, still makes the Proposal stale, while a Port Contribution generation change alone does not.
