# Define Layout contracts outside Runtime

The first release consists of `@cflow/layout-api`, `@cflow/plugin-layout`, `@cflow/layout-dagre`, and `@cflow/layout-elk`. `layout-api` depends only on `@cflow/kernel` geometry and identity types and owns the public Provider-neutral Layout Input, Layout Proposal, and Layout Engine seam, so advanced consumers can compute an uncommitted Proposal without Runtime; concrete Provider packages depend only on that API rather than Runtime or `@cflow/core`. `plugin-layout` depends on the API plus Kernel, Command, and Plugin Host seams to provide reusable Runtime integration as a factory that statically binds one Engine and one typed Command, but it provides no LayoutService or dynamic Provider Registry. `@cflow/core` re-exports the API and Runtime integration without depending on or re-exporting concrete Providers, and the seam is not considered stable until both Dagre and ELK have exercised it so one library's model does not become CFlow's accidental API.
