# Define Layout contracts outside Runtime

The first release consists of `@nodebraid/layout-api`, `@nodebraid/plugin-layout`, `@nodebraid/layout-dagre`, and `@nodebraid/layout-elk`. `layout-api` depends only on `@nodebraid/kernel` geometry and identity types and owns the public Provider-neutral Layout Input, Layout Proposal, and Layout Engine seam, so advanced consumers can compute an uncommitted Proposal without Runtime; concrete Provider packages depend only on that API rather than Runtime or `@nodebraid/core`. `plugin-layout` depends on the API plus Kernel, Command, and Plugin Host seams to provide reusable Runtime integration as a factory that statically binds one Engine and one typed Command, but it provides no LayoutService or dynamic Provider Registry. `@nodebraid/core` re-exports the API and Runtime integration without depending on or re-exporting concrete Providers, and the seam is not considered stable until both Dagre and ELK have exercised it so one library's model does not become NodeBraid's accidental API.
